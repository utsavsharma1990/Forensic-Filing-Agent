## Stub floor (STUB_FLOOR_CHARS = 25,000) and why it generalises
A 10-K that carries Item 1 (business), Item 7 (MD&A) and Item 8 (statements) cannot be under ~25k characters: the ENRON OREGON
FY1996 placeholder (cover page, one-paragraph items, exhibit list) is 15,667. Empirical gap: the shortest real filing in the local
cache of 130 annual texts is 60,252 characters; the smallest dev large-cap filing is 241,383. 25k sits inside the empty gap, and
the existing 50k `SHORT_TEXT_CHARS` warning still covers the gray zone. The rule keys on size, not on the Enron name or CIK.

## False-positive / false-negative risks (stated, not hidden)
* Cover box parsing depends on the text extraction keeping the glyphs: iXBRL cover pages that drop the box (one PG filing renders `False`) return None and fall back to the vocabulary rule. A filing with neither box nor SPAC vocabulary but that is still a shell (e.g. a real operating-less shell that never says "no operations") is missed (FN).
* The vocabulary rule can miss a SPAC that avoids the exact phrases (e.g. non-US "business combination" wording, rights-based "blank check" synonyms) and flag nothing; the cover box is then the only signal.
* The stub floor flags any registrant whose 10-K is < 25k characters, including a genuine micro-cap shell (intended) and any extraction failure that truncates text (FP risk: a failed HTML conversion of a real 10-K). `_load_year` already warns at 50k.
* The wrapper rule needs two Exhibit-13 and two incorporated-by-reference mentions plus no "total assets" in the text; a wrapper whose fetched text already includes Exhibit 13 is (correctly) not flagged.
* Successor detection takes the MODAL date near completion language; a wrong modal date inside the fiscal year would flag the wrong prior year (SPCE FY2021 yields a wrong modal date, 2020-03-10, but it is outside FY2021 and ignored). Mergers closing in a different year than the filing's own fiscal year are only picked up from the filing of that year; if that filing is not selected, the predecessor is still caught by its own cover box/vocabulary.
* Non-SPAC reverse mergers (operating company renamed) are NOT flagged as predecessor changes: out of scope (needs entity-name/CIK-history logic).
* Prior-year re-run: peer agent usually returns "unavailable" at focus-1 when peer data is missing; then Jev gets `material_change=None` for peer. The prior run uses the same peer list found for the focus year (a mild approximation) and the same filings, so the prior-year scores are those the system would have given at as_of of the later filing, not strictly point-in-time at the earlier date.
* v2 consumers (quantitative/language/network/temporal/synthesis) must still READ `filing_entity_flags`; this module only supplies and documents it.
